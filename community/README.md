# KeyHalo community content

Everything KeyHalo users share (device definitions, lighting profiles, keymap packs,
lighting effects and typing packs) lives in this folder as plain files, validated by the
JSON Schemas in [`schemas/`](schemas). The app's **Community** gallery and the
[website gallery](https://brokenwatch24.github.io/keyhalo/gallery/) are built from it.

| Folder | Content | Type (`src/core/types.ts`) | Schema | Example |
|---|---|---|---|---|
| `devices/<vendor>/` | Device definitions (USB match, driver, layouts, LEDs, capabilities) | `DeviceDefinition` | [`device.schema.json`](schemas/device.schema.json) | `devices/razer/huntsman-mini.json` |
| `profiles/` | Lighting scenes + mouse settings + keymaps to enable | `Profile` | [`profile.schema.json`](schemas/profile.schema.json) | `profiles/neon-focus.json` |
| `keymaps/` | Per-app shortcut legends, remaps and macros | `KeymapPack` | [`keymap.schema.json`](schemas/keymap.schema.json) | `keymaps/davinci-resolve.json` |
| `effects/` | Sandboxed JavaScript lighting effects | `EffectMeta` (`meta` export) | [`effect-meta.schema.json`](schemas/effect-meta.schema.json) | `effects/rain.js` |
| `typing/` | Word lists, quotes, code and lessons for the typing trainer | `TypingPack` | [`typing.schema.json`](schemas/typing.schema.json) | `typing/es-common-words.json` |
| `index.json` | **Generated** catalog of everything above | `CatalogIndex` | [`catalog.schema.json`](schemas/catalog.schema.json) | — |

## Rules

- **File name = id.** `profiles/neon-focus.json` must contain `"id": "neon-focus"`. Ids are
  lowercase kebab-case and unique per kind.
- **`$schema`** points to the schema with a relative path, which gives you autocompletion
  in VS Code:
  - `devices/<vendor>/*.json` → `"$schema": "../../schemas/device.schema.json"`
  - `profiles/*.json` → `"$schema": "../schemas/profile.schema.json"`
  - `keymaps/*.json` → `"$schema": "../schemas/keymap.schema.json"`
  - `typing/*.json` → `"$schema": "../schemas/typing.schema.json"`
- **Keys** are W3C `KeyboardEvent.code` names (`KeyA`, `Digit1`, `ShiftLeft`, `Fn`…).
  Colours are `#rrggbb`. USB ids are hex strings (`"0x1532"`).
- **Previews**: put an optional `<id>.png` or `<id>.svg` next to the file. It is shown in
  the gallery and on the website.
- **`index.json` is generated by CI**. Don't edit it by hand; it is rebuilt on every push to
  `main` (`npm run community:index` locally).

## Validation

```bash
npm run community:validate                     # everything
node scripts/validate-community.mjs --changed community/profiles/neon-focus.json
```

Besides the JSON Schemas, the validator checks:

- unique ids per kind and **file name == id**;
- valid key codes in layouts, bindings, legends and macros;
- device `match` ids are hex strings (`0x` + 4 hex digits);
- **keymap packs**: risky actions are reported as warnings so reviewers look at them:
  `launch` (starts a program), `text`, `macro` steps that type text, and `http`;
- **effects**: the `meta` export is extracted in a sandbox (`node:vm`, no globals, timeout)
  and validated, and files referencing `fetch`, `XMLHttpRequest`, `WebSocket`,
  `importScripts`, `eval` or `Function(` are rejected.

Pull requests touching `community/**` are validated automatically, and a summary is
posted as a comment on the PR.

## How the app uses this folder

1. The app downloads the catalog from
   `https://raw.githubusercontent.com/Brokenwatch24/keyhalo/main/community/index.json`
   (cached locally; a **bundled copy** is used offline).
2. **Install** downloads the single file, validates it, asks for confirmation if it contains
   risky actions, and saves it in the app data folder (`installed/<kind>/<id>.json`).
   Community effects always run sandboxed.
3. "Update available" appears when the catalog has a newer version of something you installed.

Device definitions bundled with a release work out of the box; newer ones can be installed
from the gallery without waiting for an app update.

## Sharing your work

- **Pull request**: add your file here and open a PR (see [CONTRIBUTING.md](../CONTRIBUTING.md)).
- **In-app publish**: Community → Publish signs in with GitHub, forks the repo, commits your
  file and opens the PR for you.
- **Gist**: Share → "Share via Gist" creates a public gist and a link such as
  `keyhalo://import?gist=<id>` that opens directly in KeyHalo. Gists are great for quick
  sharing; PRs put your content in the gallery for everyone.
- **"Works on my device" reports**: from the device page, report that a definition works on
  your hardware ([issue form](https://github.com/Brokenwatch24/keyhalo/issues/new?template=works_on_my_device.yml)).
  Reports move definitions to `verified`. Missing device? Use the
  [device support request](https://github.com/Brokenwatch24/keyhalo/issues/new?template=device_request.yml).
